# 奶蛙快跑 · 3D 手机跑酷小游戏

一只圆滚滚的黄色小胖龙（游戏里仍叫「奶蛙」）在三条赛道上狂奔，撞上障碍就摔跤 —— 但你可以看广告再爬起来一次。

打开页面先是**开场动画**：主角近景出场，捧着肚子笑到打颤、笑到眯眼，然后镜头拉开进入开始界面。
角色造型是照着 B 站《奶龙大笑【原版】》（BV1p2Tp6REay）一帧帧量出来、再对照 `res/奶娃照片.jpg`
定形的：**一颗正圆的球头 + 一道收腰 + 宽身子**，绿虹膜大黑瞳，详见下面「主角」一节。

## 怎么玩

**直接打开 `index.html` 就能玩**（iOS / Android 微信、Safari、Chrome 均可）。
推荐用手机浏览器打开，横竖屏自适应，竖屏体验最佳。

| 操作 | 触屏 | 键盘 |
| --- | --- | --- |
| 左右换道 | 左右滑动 | ← → / A D |
| 跳跃 | 上滑 | ↑ / W / 空格 |
| 下蹲 | 下滑 | ↓ / S |

- **跳跃只能越过两个障碍：豆包和我的刀盾**（判定顶 1.00 / 1.05，跳跃上限 1.80）。
  这两个障碍进入「现在起跳刚好能过」的距离时，**脚下会亮一圈绿色脉冲箭头 —— 看到亮就按**，
  不用自己估距离。
- **下蹲**才能钻过粉白条纹横杆。
- 其余一律**只能换道躲开**：牛来、奶牛、噜噜、猪猪侠（判定顶 1.88 / 2.00 / 1.90 / 1.98）。
- 这条规则是显式的，写在 `game.js` 的 `OB_JUMPABLE` 里，不再靠「判定顶 < 1.80 就算能跳」反推。
  改完跑 `py tools/jump_check.py` 核对：它会拿真实物理参数验证每个角色是否真的符合规则。
- 撞上障碍 → 本局结束，可**看一次广告复活**（3 秒占位广告，正式接入时替换 `playAd()` 即可）。

## 障碍物改造（第四轮）：照片生成的网格替换手写几何体

主角换成 AI 网格之后，障碍物还是手写的球 + 胶囊，同框就露馅了：
奶蛙是照片级细节，豆包是一颗椭球加两根睫毛。这一轮把五个角色也换掉。

### 先说结论：这一步成不成，八成取决于参考图

同样一条流程，五张图跑出了三种结果：

| 图 | 实际内容 | 结果 |
|---|---|---|
| `奶龙.webp` | 正面、全身、大眼、主体占满画面 | **一次成型**，五官腿脚全对 |
| `猪猪侠.jpeg` | 正面、全身、纯白底 | **一次成型** |
| `噜噜.webp` | 3/4 视角、半身、下半身被裤子盖住 | 形体对，腿部偏糊 |
| `豆包.webp` | **只拍到胸口以上** | 直接跑会缺腿 → 先补图 |
| `牛来.webp` | 表情包截图，模糊，**带「深渊凝视」文字** | 文字会被烘进贴图 → 先补图 |

所以「图不行就修图」是这条流水线的一部分，不是权宜之计。

### 补图：image-to-image 往下补全身，不是重画

对豆包和牛来，用原图做 image-to-image 的输入，让它**在原图基础上往下补**，
提示词里把已有特征逐条写死（发色 / 瞳色 / 衣服 / 鼻吻形状），只描述缺失的部分。

两个必须注意的点：
- **生成图右下角带平台水印**。直接裁掉会切到鞋底，正确做法是采样背景色把水印块涂平。
- 补出来的图仍然要 1024 长边，尺寸不统一会在贴图烘焙时出现细节差。

产出统一放 `res/ref3d/`。

### 工具：`tools/prep_actor.py`

原始 GLB 是 **23 MB**（三张 4096² PNG 贴图），网页里根本不能用。
一条命令压到 **0.37 MB**，同时转成 base64 的 `.js`：

```bash
py tools/prep_actor.py res/models/raw/nailong.glb res/models/actors/nailong 1024
```

为什么不直接 `fetch` 那个 glb：`file://` 下会被 CORS 拦，只能用 `<script>` 引入。
所以模型是 base64 内嵌的，再由 `lib/glb-lite.js` 同步解析（不走 GLTFLoader、不联网）。

### 游戏端：一个 `glbActor()` 吃下所有角色

```js
OB.niulai = function () {
  if (USE_GLB_ACTORS) {
    var a = glbActor('ACTOR_NIULAI', { h: 1.37, hitH: 1.26, hitK: 0.80, name: '牛来' });
    if (a) return a;
  }
  /* 旧代码原样保留，glbActor 返回 null 时自动兜底 */
};
```

它负责三件事：按目标身高缩放、脚底对齐 `y=0`、按包围盒给碰撞盒。
原型只在第一次 spawn 时解析，之后每次都是 `clone()`（共享几何与贴图，不重复上传显存）。

`h` 不是随便填的：必须对齐旧模型的视觉高度，否则「跳得过去 / 必须换道」的难度会变。

### 最终结果

| 角色 | 文件 | 面数 | 体积 | 状态 |
|---|---|---|---|---|
| 奶龙（收集物） | `actors/nailong_glb.js` | 9,619 | 0.37 MB | ✅ 已替换 |
| 猪猪侠 | `actors/zhuzhuxia_glb.js` | 12,306 | 0.47 MB | ✅ 已替换 |
| 噜噜 | `actors/lulu_glb.js` | 10,716 | 0.40 MB | ✅ 已替换 |
| 豆包 | `actors/doubao_glb.js` | 9,509 | 0.48 MB | ✅ 已替换（用补全身图） |
| 牛来 | `actors/niulai_glb.js` | 12,317 | 0.50 MB | ✅ 已替换（用补全身图） |
| 我的刀盾 | `actors/daodun_glb.js` | 12,527 | 0.59 MB | ✅ 已替换（按宽度定标） |

> **六个角色全部完成，体积从 21~29 MB 压到 0.37~0.59 MB。**
>
> 牛来和刀盾是在 10-30 早上补跑的。前一天撞的是 `hy-3d` 的**每日提交次数**
> （5 次/天），不是余额 —— 账户积分再多，第 6 次也提不上去；计数器按**自然日
> 0 点**重置。另外还有个**并发槽位上限 2**，同时最多跑两个任务。
> 两条限制都写进了 `游戏制作Skill（图生3D）` 技能的踩坑表。
>
> **刀盾的缩放要特殊处理**：原图是趴姿，模型世界尺寸 宽 1.90 × 高 1.44 × 深 1.89，
> 宽高比 1.32。按身高定标会把它拉成一坨 2.58 米宽的趴地蒲团、压两条道。
> 所以 `glbActor` 新增了 `opt.w`（按目标全宽定标，身高由宽度反推），
> 刀盾传 `w: 2.16`，反推身高 ≈ 1.63，碰撞盒顶部 1.50。
> 顺带改变了玩法定位：玩家跳跃上限 1.78 > 1.50，这个障碍从「必须换道」
> 变成「可跳可换道」—— 模型就这么矮，硬撑判定会让玩家撞到看不见的空气。

| 断言 | 结果 |
|---|---|
| 六个模型在游戏内摆齐 | ✅ `.shots/t_new_actors.png` |
| 近看比例与贴地 | ✅ `.shots/t_near.png`（`#show=near` 调试参数） |
| 六角色并排预览 | ✅ `res/models/actors/viewer.html` |

原始 GLB 都在 `res/models/raw/`（每个 22~24 MB），不参与运行，留着以后想换贴图精度时重压。

### 踩到的坑

| 现象 | 原因 | 解法 |
|---|---|---|
| 角色躺倒 / 头朝下 | GLB 顶点是 Z-up，靠节点自带的绕 X 轴 +90° 旋转转成 Y-up | `glb-lite` 会应用这段 TRS，游戏里别再多转一次；但在 Python 里读顶点必须自己换算 |
| 一摆出来就撞死 | 调试摆位时把障碍物放在了玩家所在车道 | 调试参数 `#show` 固定摆 0 号与 2 号道 |
| 收集物像展示台一样转圈 | 旧蛋是抽象形状，换成有脸的奶龙后 360° 旋转很怪 | 改成左右摆头 + 上下浮 |
| 模型比碰撞盒宽一圈 | 包围盒算进了张开的手臂/耳朵 | `hitK` 压横向手感系数，别改 `h` |



## 第五轮：牛来放大 + 把「能跳」变成真的能跳

豆包和我的刀盾看着不高，玩家起跳明明能跨过去，实战里却百分之百撞死。

**根因不是判定写错，也不是模型太高，而是跳跃抛物线太陡。**

原来 `JUMP_V 13.6 / GRAVITY 52`：最高点 1.78 米，但脚底高于 1.47 的时间只有
**0.22 秒**；而障碍穿过判定区需要 0.214 秒（起步速度 12.5 m/s，判定区宽 2.68 米）。
两个数几乎相等 —— 容错只剩 **3 厘米**，等于要求玩家把按键精确到一帧。

### 改法：高度不动，把抛物线拉扁

| | 改前 | 改后 |
|---|---|---|
| `JUMP_V` | 13.6 | **10.4** |
| `GRAVITY` | 52 | **30** |
| 最高点 | 1.778 米 | 1.803 米（几乎没变，视觉察觉不到） |
| 滞空 | 0.52 秒 | 0.69 秒 |
| 脚底高于 1.47 的窗口 | 0.22 秒 | 0.31 秒 |

起步速度下各障碍的跳跃容错：

| 障碍 | 判定顶 | 改前容错 | 改后容错 |
|---|---|---|---|
| 豆包 | 1.47 | 0.13 米 | **1.15 米** |
| 我的刀盾 | 1.50 | 0.32 米 | **1.31 米** |
| 牛来 | 1.58 | 0.13 米 | **1.02 米**（第六轮改回「只能躲」，见下） |
| 噜噜 | 1.90 | 跳不过 | 跳不过 |
| 猪猪侠 | 1.98 | 跳不过 | 跳不过 |

上限压到 1.80 是刻意的：噜噜判定顶 1.90、猪猪侠 1.98，必须严格高于 1.80
才能保证这两个「永远跳不过」。留 0.1 米余量是给数值积分的抖动。

> 这里有个容易踩的坑：只看「最高点 > 判定顶」就断定能跳过去是错的。
> 决定成败的是**脚底高于判定顶的持续时间**和**障碍穿过判定区的持续时间**之比。
> 前者由抛物线在顶部有多「平」决定 —— 改 `GRAVITY` 就是改这个「平」，改 `JUMP_V` 是改高度。

### 牛来放大

身高 1.37 → **1.72**（宽 0.91 → 1.15）。它原来是六个角色里最矮的一只，
站在路中间像个赠品模型。碰撞 `hx/hz` 保持 0.62 不动 —— 视觉半宽 0.575 小于 0.62，
判定仍比看上去略宽，手感是宽容的。

### 验算工具 `tools/jump_check.py`

把真实判定条件（`py >= hitH - 0.02`、判定区半宽 = `hz + 0.46`）和抛物线一起算，
直接输出每个障碍在各速度下的容错米数，改参数前先跑一遍：

```bash
py tools/jump_check.py 10.4 30      # 可传任意 JUMP_V / GRAVITY 试算
```

### 游戏内调试参数

- `#auto&hop` —— 冻住世界，把一只豆包摆到右侧道，玩家落地就再跳。
  截图能直接看出脚底有没有高过障碍顶；`#hop=shield` 换成刀盾。
- `#auto&bot` —— 自动跑：能跳的就跳、跳不过的换道，左下角实时显示「起跳 / 越过 / 死亡」计数。

> headless 截图下虚拟时间和游戏时间不同步，`#bot` 跑不出长距离，
> 想真正跑起来看统计得开真浏览器。跳跃是否合格以 `jump_check.py` 的容错米数为准。

## 第六轮：只有豆包和刀盾能跳，其余一律只能躲

上一轮的「能不能跳」是**隐式**的：判定顶 ≤ 1.80 就算能跳。牛来判定顶 1.58，
于是它被归进「能跳」那一档 —— 可它模型才 1.72 米，跟旁边 1.05 的豆包、1.63 的刀盾
混在一档，观感上像个误入的小号道具。

这一轮把规则**显式化**，并让模型跟上规则：

| 角色 | 模型身高 | 判定顶 | 结论 |
|---|---|---|---|
| 豆包 | 1.05 | 1.00 | ✅ 可跳（起步窗口 0.59 秒） |
| 我的刀盾 | 1.63（按全宽 2.16 反推） | 1.05 | ✅ 可跳（起步窗口 0.52 秒） |
| 牛来 | **1.96**（原 1.72） | **1.88** | ❌ 只能躲 |
| 噜噜 | 2.06 | 1.90 | ❌ 只能躲 |
| 猪猪侠 | 2.15 | 1.98 | ❌ 只能躲 |
| 黑白奶牛 | 2.00 | 2.00 | ❌ 只能躲 |

三条设计考虑：

1. **规则写死在 `OB_JUMPABLE`**，不再靠高度反推。以后谁调了跳跃参数或模型身高，
   可跳名单都不会悄悄变 —— 以前那种写法，改一个 `hitH` 就能把一只障碍从「必须躲」
   变成「可以跳」，而没有任何人会发现。
2. **牛来的模型是真的做高了**，1.72 → 1.96，不是只把判定偷偷抬上去。
   模型不动只抬判定的话，玩家看着一头 1.72 米的牛、脚明明高过它头顶却撞死，只会当成 bug。
   判定顶给到 1.88，比跳跃上限 1.80 高 8 厘米 —— 怎么跳都够不着。
3. **大小即规则**：能跳的两个判定顶都在 1.05 米以下，跳不过的全在 1.88 米以上。
   玩家不用记名单，看角色大小就知道该跳还是该躲。

顺带把 `hx/hz` 从 0.62 等比放大到 0.66 / 0.72，跟 1.96 的身高匹配，
仍然比视觉半宽略窄，擦边是宽容的。

### `jump_check.py` 升级成规则核对器

它现在会从 `game.js` 里读 `OB_JUMPABLE`，再拿真实物理参数逐条验：
说能跳的必须三个速度下都有正容错，说跳不过的必须一条正容错都没有。
任何一条对不上就打印 ✗ 并 `exit 1`。

```
障碍                 判定顶   越过线   判定深 | 几米外起跳能过去              | 规则    | 核对
豆包   doubao       1.00   0.94   0.38 | 2.54 ~ 9.96 米（窗口 0.59 秒） | 可跳    | OK
刀盾   daodun       1.05   0.99   0.84 | 2.98 ~ 9.52 米（窗口 0.52 秒） | 可跳    | OK
牛来   niulai       1.88   1.88   1.44 | 够不着                       | 只能躲  | OK
奶牛   cow          2.00   2.00   1.40 | 够不着                       | 只能躲  | OK
噜噜   lulu         1.90   1.90   1.40 | 够不着                       | 只能躲  | OK
猪猪侠 pigman       1.98   1.98   1.28 | 够不着                       | 只能躲  | OK
✓ 规则自洽：豆包、刀盾能跳，其余只能躲。
```

### 新增两个调试参数

- `#hop=bun|shield|niulai|cow|lulu|pigman` —— 以前只能 `hop` 和 `hop=shield` 两种，
  现在任意角色都能摆出来看。跳不过的角色摆到跟前也不会撞死（`G.noHit`）。
- `#height=1.80` —— **把玩家钉死在指定高度**，重力不生效。
  这是这一轮最有用的一条：headless 的虚拟时间和游戏时间不同步，靠 `#hop` 抓腾空帧
  经常抓到刚起跳的一瞬，截图不可信。`#height` 是纯静态摆位，拍出来就是那个高度。

配合 `#show=all&height=1.80` 能一张图看清「脚底 1.80 米 vs 每个角色头顶」的高低关系。

> 注意：障碍摆在 `z=-4.6` 而玩家在 `z=0` 时，**不同深度的像素高度不能直接比** ——
> 远处的会被透视压到更高。要对比必须用 `#hop=xxx&height=1.80`，障碍在 `z=-0.6`，
> 深度差只有 0.6 米，误差可以接受。

## 第七轮：还是跳不过 → 根因是「窗口秒数」不是「容错米数」

第六轮之后玩家实测仍然跳不过豆包和刀盾。第七轮把责任查清了，分三层：

1. **豆包的判定盒是虚胖的（真正的 bug）**。`hx 0.66 / hz 0.88` 是照抄旧手写模型的，
   那是给一个「胖墩」留的判定。AI 模型实际只有 宽 0.48 × 深 0.41（按身高 1.49 缩放），
   判定盒深 1.76 米比模型宽出 **1.35 米** —— 玩家看着豆包已经跑到身后了，
   那个看不见的盒子还锁着他。改按真实包围盒算并留 5~6 厘米宽容：`hx 0.30 / hz 0.26`。
2. **刀盾是趴姿、纵向 1.44 米**，判定深 0.72 意味着要在它上方待 2.4 米的路程。
   判定深收到 0.42（见 `OB_HZ`）：碰撞触发点从模型中心前 1.18 米缩到 0.88 米，
   模型鼻子本来就在前 0.95 米 —— 撞上来时玩家正好贴着它的脸，看不出差别。
3. **指标选错了**。一直在报「容错几米」，但米数除以速度才是人反应得过来的量。
   现在统一报**窗口秒数**，要求「可跳」的窗口 ≥ 0.25 秒。

### 最终参数与实测（真实碰撞代码跑出来的，不是公式）

`JUMP_V 7.1 / GRAVITY 14`（最高点 1.74，滞空 1.01 秒 —— 抛物线很平，这是刻意的）：

| 障碍 | 判定顶 | 判定深 | 起跳区间（起步 12.5 m/s） | 窗口 |
|---|---|---|---|---|
| 豆包 | 1.47 → **1.00** | 0.52 → **0.38** | 4.1~8.4 米 → **2.55 ~ 9.95 米** | 0.34 → **0.59 秒** |
| 我的刀盾 | 1.50 → **1.05** | 0.84 | 4.2~8.3 米 → **3.00 ~ 9.50 米** | 0.32 → **0.52 秒** |
| 牛来 / 奶牛 / 噜噜 / 猪猪侠 | 1.88~2.00 | — | 够不着 | — |

> 第七轮收尾时这两个窗口是 0.34 / 0.32 秒，玩家实测仍然跳不过 —— 箭头右边是
> 第八轮改完的结果。到这一步，「继续磨抛物线和判定盒」这条路已经走到头了，
> 再改下去只会把窗口从 0.34 挪到 0.36，玩家的手感不会有任何变化。

### 新工具：`#simtest` —— 用游戏自己的碰撞代码做回归

公式推算和真实代码之间可能差一个 `>=` 号。`#simtest` 在页面里跑一个**确定性模拟**：
固定 1/60 步长、逐帧走真实的 `updateWorld / updatePlayer / checkCollisions`，
对每个角色扫出「从几米外起跳能过去」的完整区间，写进 DOM，

## 第八轮：窗口 0.34 秒还是跳不过 → 把「矮」做进模型，把「时机」画到地上

第七轮验收过了：判定盒按真实包围盒算、窗口 0.32~0.34 秒、公式和 `#simtest`
两边都对得上。玩家第四次反馈还是跳不过。这一轮承认一件事：**数值对，不代表玩得过。**

### 为什么 0.34 秒不够

按一下键确实只要 0.1 秒，但跑酷玩家的真实操作链是
「看见障碍 → 判断还有几米 → 决定起跳」，这一整条链吃掉的时间比窗口本身还长。
更要命的是**第三人称追尾视角没有可靠的深度参照物** —— 你能量出窗口，玩家量不出距离。

继续磨参数也磨不出空间了：跳跃峰值被牛来锁死在 1.74（判定顶 1.88），
「把跳跃加高」这条路早已到尽头。

### 改法：三条都不是调参

| | 改前 | 改后 | 说明 |
|---|---|---|---|
| 豆包身高 | 1.49 | **1.05** | GLB 出来多大就用多大，从来没人问过「它该多高」。按人设它就是矮个 |
| 豆包判定顶 | 1.47 | **1.00** | 玩家（1.45 米）从她头顶跨过去，视觉和判定同时成立 |
| 刀盾判定顶 | 1.50 | **1.05** | 趴姿 1.63 里上半截是举起的刀和盾，只算真正挡路的那部分 |
| 越过容差 | ×0.95 百分比 | **固定 6 厘米** | 百分比折扣对矮障碍几乎没收益，固定值对所有角色一视同仁 |
| 起跳提示 | 无 | **脚下圆环 + 头顶箭头** | 两个信号分工：脚下圆环 =「现在按」（只在起跳区间亮），头顶箭头 =「这个能跳」（半透明绿色，远远就挂着） |

窗口从 **0.34 / 0.32 秒 → 0.59 / 0.52 秒**，接近翻倍，而且不再依赖玩家的目测能力。

起跳提示的实现（`jumpCueRange` / `updateJumpCue`）跟 `checkCollisions` 共用同一套
`JUMP_V / GRAVITY / hit`：**灯亮着按，就一定过得去**，不会漂移。
两个易错点记下来：cue 的材质必须 `new`，不能共用 `matB`（那是全局缓存，
每帧改 `opacity` 会污染别处）；跨道时不亮提示，否则玩家会在错误的道上起跳。

头顶箭头（`buildJumpArrow` / `updateJumpArrow`）是另一套信号，别跟圆环混为一谈：

- **圆环管时机，箭头管分类**。圆环只在「此刻起跳刚好能过」的距离区间内、且在本道时亮；
  箭头只要障碍是可跳类型就一直挂着，任何距离、任何道都显示——玩家先靠它认出目标。
- 箭头亮度三档：窗口内最亮最快脉冲（按！）> 平时 0.30 > 玩家在空中 0.14（按了也没用）。
- 障碍距离 < 1 米时淡出：玩家马上要穿过箭头位置了，糊在脸上反而挡视线。
- 挂点高度取 `max(判定顶, 包围盒顶 × 0.85) + 0.30`：只按判定顶摆会插进刀盾竖起来的
  刀里，只按包围盒摆又飘得太高。**量模型要在挂提示之前**，否则包围盒会算进提示自己。

### 顺带补的手感：土狼时间 + 跳跃缓冲

窗口再宽，「按了没反应」也会毁掉一切：

- **土狼时间 0.10 秒** —— 脚离地后这点时间内仍可起跳；
- **跳跃缓冲 0.13 秒** —— 落地前按下跳跃，落地那一帧自动兑现；
- 两者都通过统一的 `launchJump()` 入口，避免状态被两处代码各改一半。

### 验收升级：`simBot()` —— 固定步长跑完整局

`#simtest` 只验「单个障碍能不能跳过去」。要验「这局游戏能不能玩」，得让 bot
在**真实游戏循环**里连跑几十秒：`simBot(30)` 用 1/60 固定步长走真实的
`updateWorld / updateEntities / updatePlayer / checkCollisions`，bot 自己判断跳/换道/蹲。

```
BOT 3×30秒固定步长全程模拟: 起跳 5 次 · 死亡 0 次  ✓ 全程无伤
```

> **不要信 `#bot` 的 DOM 统计**：headless 的虚拟时间推不动 `requestAnimationFrame`，
> 它能显示「起跳 0 次 · 死亡 0 次」而角色早就撞死了（"距 1 米"就说明游戏根本没推进）。
> 截图能跑起来是因为 `--screenshot` 模式会把文章推到"页面稳定"为止，两者不是一回事。

写 bot 的时候挖出三个**通用** bug，都值得记住：

1. **跳跃预测必须用欧拉积分**。解析抛物线比真实积分高 7 厘米，边界帧 bot 会
   「以为能过」然后一头撞上 —— 玩家也会被同一件事骗。
2. **横杆 `hx = 3.9` 横跨三条道**。近障碍表按「障碍中心在哪条道」算的话，
   玩家换到边上就看不见它了。必须按判定盒覆盖来算。
3. **蹲要每帧续**（相当于玩家按住下键）。点一下只有 0.62 秒，
   对着横杆常常差最后 0.07 秒被扫到。

|---|---|---|

## 主角改造（第三轮）：修穿模 + 修跑姿

这一轮修的是两件用户直接看得见的事：**眼睛和嘴穿模**、**跑步很奇怪**。
两件事都不是"参数没调好"，而是**坐标系用错了**。

### 跑姿像钟摆：伪骨骼的髋部高度用错了单位

伪骨骼里 `h = -z` 是模型 raw 坐标下的高度（脚底 −0.95、头顶 +0.95），
但代码里写的是 `HIP_Y = 0.62` —— 那是**世界坐标**下的髋部高度。
换算成 h 应该是 `0.62 − 0.95 = −0.33`。差一个 0.95 的偏移，
铰点就从髋部飞到了**头顶附近**，于是"腿"的判定变成"除头以外的一切"，
整个身体绕着脑袋做钟摆运动 —— 这就是"跑起来很怪"的真正原因。

| 参数 | 错的 | 对的 | 含义 |
|---|---|---|---|
| `HIP_H` | `0.62` | `-0.33` | 髋部在 h 坐标下的高度 |
| 枢轴 `cz` | `-0.62` | `+0.33` | 旋转中心在 raw z 上的位置（世界 y≈0.62）|
| `LEG_CUT` | `0.30` | `0.22` | 髋以下多远的距离内完成 0→1 权重过渡 |
| `LEG_GAIN` | `0.52` | `0.80` | 应用比例（配合摆幅 0.70 rad，实际约 32°）|

另外补了一段**脚掌反旋**：踝点（世界 y≈0.18）以下按 55% 反向回转，
不然整只脚会跟着腿一起翻起来像鳍。

### 嘴穿模：笑缝在三维里是弯的

量出来的事实：笑缝沿脸颊往下弯，从左到右 **z 由 +0.26 变到 +0.18**（深度差 8 cm）。
所以任何解析曲面（球、球冠、平面）贴上去，必然一端顶出脸颊、一端埋进肉里。

解法是**不用解析几何**：在模型表面按椭圆足迹采样，
每个采样点回查真实曲面坐标、再沿法线抬 4 mm，生成一片和脸完全同形的网格
（`res/models/mouth_patch.js`，131 顶点 / 260 三角）。采样来自自写的正交光栅化 +
z-buffer 反查（`rast2.py`），不是靠眼睛估。

还有一个隐蔽的坑：`setMouthOpen` 会改 `mouthG.scale.y` 做张合动画。
如果贴片顶点是**绝对坐标**，缩放就会绕 rig 原点（脚底）进行，嘴会瞬移到肚子上。
所以贴片顶点必须先变换到 `mouthG` 自己的局部系（`matrix.compose(c, quat, 1).invert()`）。

### 关于眼睛

上一版盖的"大眼球"是错的：整颗头是 3/4 侧转的，贴图里两颗眼在
**x = −0.211 / +0.038**（光栅化聚类实测），根本不对称。
用 ±0.132 这种对称值去盖，必然一颗浮在头顶、一颗压进脸颊。
现在**不盖了** —— 这双眼 AI 做得又准又像，只在瞳孔上点一颗高光。

### 这一轮的踩坑

| 现象 | 原因 | 解法 |
|---|---|---|
| 跑起来整个身体像钟摆 | 伪骨骼铰点用了世界坐标当 h 用，铰点落在头顶 | `HIP_H = -0.33`（见上表）|
| 脚像鳍一样翻转 | 脚跟着腿整体旋转 | 踝点以下按 55% 反向回转 |
| 张嘴的洞比笑缝低一截 | 用单个像素的法线定向，在下巴转折处法线朝下，椭圆足迹整体沉下去 | 改用嘴部小块**加权平均法线** |
| 张嘴片一端穿出脸颊 | 笑缝在 3D 里是弯的（z 差 8 cm），平面贴片必然穿 | 从模型表面采样生成贴脸网格 |
| 张嘴时嘴瞬移到肚子上 | `scale.y` 张合动画绕的是 rig 原点 | 顶点先变换到 `mouthG` 局部系 |
| 顶视图配色对不上 | glTF 的 UV 原点在左上（V 向下），three 的 `Texture.flipY` 与之相反 | 采样时 `ty = v*(H-1)`，不是 `(1-v)*(H-1)` |
| 从截图量坐标老是差几十像素 | 两次截图的相机不在同一位置，比例尺不同 | 改用正交光栅化，屏幕坐标与模型局部坐标一一对应 |

## 主角：照着 `res/奶蛙照片.jpg` 逐行量出来的梨形

这一版不再"设计比例"，而是把参考图**逐行扫描**、把每一行的左右边界换算成半径，
直接生成侧影表。参考图 474×559，主体占 **434px 高、274px 宽**，左右中心在 x=179。

|---|---|---|
| 躯干最宽半宽 | **137px → r 0.709** | 0.500（窄了 40%）|
| 头半宽 | **62.5px → r 0.317** | 0.353（相对躯干反而更宽）|

| 头 / 肩 | **58%** | 71% —— 头"显小"其实是肩太窄造成的错觉 |
| 头两侧（rel 1.29→1.44）| r 0.331→0.3175，**几乎平行** | 做成球面 → 保龄球瓶 |
| 整条轮廓的局部极小 | **没有**（无腰、无脖子）| 收腰 28% + 细颈 0.324 |
| 大腿 / 脚踝 | **0.231 / 0.083 = 2.8 倍** | 0.204 / 0.144 = 1.4 倍（两根等粗水管）|

- **BODY_PROF 是量出来的，不是设计出来的**：48 个控制点 → Catmull-Rom 85 点 → Lathe 168 段。
  关键行（参考图 y → 相对高度 → 半径）：`y=136→rel 1.39→0.318`（头最宽）、
  `y=176→rel 1.19→0.457`（肩头）、`y=206→rel 1.04→0.559`（肩最外）、`y=286→rel 0.63→0.709`（最宽）。
- **溜肩**：从腮（rel 1.29，r 0.331）到肩最外（rel 1.04，r 0.559），0.25 的高度里收放 0.23 的半径，
  斜率从 0.34 一路加到 1.15 再减回 0.7，中途没有折角。这一段做平 → 头成了花瓶口；
  做成球面的下半截 → 保龄球瓶。
- **没有腰**：轮廓从头顶到肚子单调外扩，一个局部极小都没有。
- **腹部是前后不对称的**：`BELLY_BULGE 0.155` 只推正面（`pow(front, 2.4)`），后背反而收 `-0.012`。
  纯旋转体会得到一个"竖直的蛋"，侧面看不出肚子。
- **配色**：主体是偏绿调的奶黄（头顶 `#E4DF7C` → 脸颊 `#DEC065` → 躯干 `#D6B458` → 腿根 `#C79A44`），
  手脚是橄榄褐 `#8A7248` / `#7C6740`。
- **眼睛**：`EYE_R 0.114`（眼直径占头宽 36%）、`EYE_X 0.148`、鼓出 `0.066`。
  抛物面圆顶（`eyeDome`），顶点色由内到外：黑瞳 `#0C0F08` → 绿虹膜 `#4C7A26` → 暗绿边 `#2C4A16`。
  `EYE_Y` 卡在 **2.078** 是有原因的：再高 0.03，眼球上缘就顶进头顶迅速收窄的那一段，
  圆顶会被 `faceZ` 压平成一条直线。
- **嘴**：`LIP_Y 1.828`，±0.170 的**细横线**，两端微翘。`FACE_A` 只有 0.054 —— 侧脸是一道平滑的弧，没有喙。
- **手臂**：`taperTube()` 放样的一根**粗细可变**的管（`TubeGeometry` 是等半径的，做出来是香肠）。
  半径沿 t 从 **0.150（肩）→ 0.146 → 0.140（上臂中）→ 0.118（肘）→ 0.107（前臂）→ 0.056（腕）**，
  腕只有肩的 37%。
  **样条分两段，中间是一个真折角**：肩 → 肘是近乎直线的下坡（x 0.08→0.258 单调增、y 0.006→−0.226
  单调减），到肘后的 0.072 里把 z 从 0.082 甩到 0.196 —— 折角一眼可见。
  `ag.position` 在 `(s·0.44, 1.525, 0.015)`，起点 y **必须压在 0.040 以下**：
  0.175 时管子在肩上鼓出一个拱顶（顶到 y≈1.85，比肩还高），整条手臂读成"提手"，
  从身体上方绕出去再兜回来，没有上臂、没有肘。
- **手**：参考图里是一双**人类的手**，不是"圆球掌 + 尖爪"。结构分四层：
  - **掌**：一颗**超椭球** `boxBall(0.128, 0.088, 0.054, 3.2)`（`|x|^n+|y|^n+|z|^n=1`，n=3.2 才有平顶直边），
    掌底再放宽 16% 成梯形；掌宽 0.256、高 0.176、厚 0.108，宽厚比 2.4。掌根另有一颗 0.072 的球接腕。
  - **4 指**：每根一根 `taperTube` 弯管（r 0.023~0.026，长 0.116~0.152），
    指根最粗、指尖 86%，末节向肚皮勾，指尖一颗 0.98r 的球封圆。
    长度顺序 中指 > 食指 ≈ 无名指 > 小指，`z` 各有 ±0.005 的错落（中指最靠前）。
  - **拇指**：从掌的**内侧**（靠身体中线）中段伸出，两节、向内撇 45°、朝前倾 18°，
    必须在掌的**前侧**（z 0.040 > 掌厚一半），否则整根嵌在掌的厚度里，正面只能看到一条边。
  - **腕**：收细到 0.052，掌根 0.072 从外面把它包住 —— 手腕是全身最细处，不能比手粗。
- **腿**：一段 `LatheGeometry`，**0.231（大腿）→ 0.180（膝）→ 0.083（脚踝）**。
  脚踝只有大腿的 36% —— 这是"小腿很细"的来源。拉成等锥（0.204→0.144）就是两根水管。
- **脚**：一颗**下半截钳平**的超椭球 + 三道沿脚长的形变，脚底落在地面 y≈0（local −0.585）。
  - **钳平**：`y < FOOT_CUT` 的顶点全部搬到 `FOOT_CUT`。球压扁做脚，底面是一段弧，
    从下往上看是个蛋 —— 跳跃时能看到悬空的弧底，落地只有正中间一点受力。
  - **高度包络** `FOOT_HK`：后跟 0.56 → 踝下 1.06（脚背最高）→ 趾根 0.46，脚背向前斜降。
  - **宽度包络** `FOOT_WK`：后跟 0.60 → 跖球 1.00（最宽）→ 趾端 0.90。
    早先只按 `sin` 给了一个"中段最宽"的鼓包，前后几乎一样宽，整只脚就成了一只圆头拖鞋。
  - **4 瓣趾垫**：前缘按 x 分成 4 个瓣（`cos(4π(u+0.75))`），瓣顶前推 0.052、瓣沟后退，
    把脚趾**雕进同一个曲面**。早先外挂 4 颗椭球：侧面看是粘在脚边的四颗豆子，正面又大半埋进脚里。
  - **配色**用顶点色：脚背 = 腿色 `#C9A64D`，`smoothstep(0.80, 0.98, t)` 渐变到趾端 `#4A3A1E`。
    深色是同一张皮上的颜色；贴一块深色"鞋头"会让整只脚变成皮鞋。
  - `ft` 独立一组，只绕 y 外八 12.6° —— 腿外撇 11.7° 但**脚不能跟着斜**，否则会变成踮脚。
    踝点落在脚长 40% 处（后跟短、前掌长），所以脚网整体前移 0.046。
- 总高 `0.560 + 1.752 = 2.312`（`root.scale 0.98` 后约 2.27），宽/高 ≈ 0.61。

### 踩过的坑（改这个模型前建议先读）

| 现象 | 原因 |
|---|---|
| 整体像一根柱子 | 腰 0.410 / 头 0.420 写成了两个几乎相等的值，从肚子往上就是一根 0.41 的直筒 |
| 收腰 + 细颈之后像"棒棒糖"或"另一种生物" | 参考图的轮廓**根本没有局部极小**，收腰是从别处借来的设定 |
| 头做成球 → 像保龄球瓶 | 参考图的头两侧几乎平行（rel 1.31→1.53 只掉 0.016），是"上端圆弧的竖长圆角柱" |
| 腿像从身体下面长出来的球 | 身体底部 r 只有 0.185，而腿 r 0.205 —— 腿比臀还粗。底部必须先鼓到 0.5 以上 |
| 背面一条水平的"底切"，腿像插在一块板上 | 剖面最下面 3 个点在 0.04 的高度里把半径拉到 0.3；改成半圆收底，用 0.16 的高度展开 |
| 裆部以下能看到一个洞 | 剖面第一个点的 r 不是 0，Lathe 底下就是开口的 |
| 肚皮是一片死白 | 顶点色 0xEDE2D4 + `shininess 32` 的高光；降到 0xD6C7B4 + `shininess 5` |
| 手被肚子整个吞掉 | 肚子最宽 0.706 + 前凸 0.098 ≈ 0.80，手的 z 必须到 0.75 以上才露得出来 |
| 手指朝下 → 像动物的爪子 | 参考图的手是**扶着肚子**的，手指顺着肚皮朝上 |
| 手指又长又细 → 像鸡爪 | r 0.033 / 长 0.100 太细长；改 r 0.037 / 长 0.070 并减小间距 |
| 肩上鼓起一个包（像垫肩） | 额外加的"三角肌"球；删掉，靠手臂自身半径和位置形成肩宽 |
| 肘部一道斜切口 | 上臂 + 前臂两段胶囊拼接；换成一根 `TubeGeometry` |
| 侧面手臂像悬在胸前的香蕉 | 肩端封口球露在身体外；起点要深埋进肩关节（`x + 管半径 < 该高度半径`）|
| 眼包边缘一圈锯齿 | 球穿进脸里，两个曲面的交线在网格上永远是锯齿；改用从脸面起鼓的圆顶 |
| 眼包正中一块平斑 | 圆顶极点法线被周围三角形平均掉了；手动设 `normal(0,0,1)` |
| 正中间一道贯穿全身的粉白竖线 | 肚皮顶点色里 `aw` 兜底成 0.02，超出 y 范围后 x=0 那条经线全程 `d=0` |
| 头顶一根小「呆毛」 | 剖面最后两点的跨度太大，Catmull-Rom 在极点外插出尖 |
| 笑的时候只剩两道眉毛 | 整颗眼隐藏、只留一条 torus 弧；改成把眼球竖直压扁（`scale.y 0.17`）|
| 眼睛上缘被削成一条直线 | `EYE_Y` 抬高 0.03 后，眼球上缘伸进头顶收窄段，`faceZ` 的 `sqrt` 被 clamp 到 0.0002，整个圆顶被压平 |
| 眼球边缘像贴了一张贴纸 | 顶点色最外圈用了橙褐 `#B08B3E`；参考图那圈是暗绿，换成 `#2C4A16` |
| 正面两肋各凸出一个尖角，像鱼鳍 | 手臂半径加到 0.136 后，样条在肘部急转（x 先增后减），管外侧被顶出一个尖；改成肩→肘走一条偏移极小的弧 |
| 背面看是两个"肩垫" | 手臂样条走正侧面（z 只有 0.13），从背后看就是贴在身侧的两片；挪到侧前方 45°（z 0.39）|
| 上臂完全看不见，只剩两只手挂在肚皮上 | 肩加宽到 0.55 后，早先那条 x 到 0.63 的手臂整根埋进身体；肘部要顶到 0.65 并前移 |
| 腕口露出一圈管口 / 掌根外凸一个尖 | `TubeGeometry` 两端是开口的，且腕比掌粗；两头各加一颗球封成圆头 |
| 肚子底部一圈"裙边"折痕 | 剖面 `[0,−0.012]→[0.148,0.002]`，0.014 的高度里半径从 0 拉到 0.148，等于加了个平底盘；改成斜率均匀递减的圆弧，底点埋到 −0.034 |
| 两脚分得很开，像企鹅 | `limb.rotation.z = ±0.075` 外八把脚推出去了；降到 ±0.016 |
| 手臂像两只"提手"从肩上方拱出去 | 样条起点 y 0.175 高于肩线，管子在肩上鼓出拱顶（顶到 y≈1.85）；压到 0.040 |
| 手臂是一根光滑的 C 形弧，没有肘 | 肩→肘中间没有直线段，转折被 Catmull-Rom 抹平；先走直线到肘，再在 0.072 内把 z 甩 0.114 |
| 脚像一只圆头拖鞋，前后一样宽 | 宽度只按 `sin` 给了"中段最宽"的鼓包；改成 `FOOT_WK` 包络（后跟 0.60 / 跖球 1.00） |
| 脚趾是粘在脚边的四颗豆子 | 外挂 4 颗椭球，正面大半埋进脚里、侧面只露出球面；改成把 4 个趾瓣雕进前缘曲面 |
| 贴一块深色"鞋头" | 独立几何浮在脚背上，边界有一条硬缝，正面看就是穿了一双皮鞋；改用同曲面顶点色渐变 |
| 脚底在跳跃时露出悬空的弧底 | 球压扁做脚，底面是一段弧；`y < FOOT_CUT` 全部钳平 |
| 大脚趾/趾缝处顶面折出一道黑缝 | 趾瓣的竖向起伏给到 0.030，瓣顶与瓣沟的两排顶点交叉自穿；降到 0.017 |
| 手指像一串竹节虫 | "两节胶囊 + 关节球"：胶囊两端本身就是半球，拼接处必然鼓出一个核桃大的台阶；改成一根 `taperTube` 渐细弯管 |
| 指尖变成削尖的铅笔 | 管端半径收到 0.54r，封口球只有 0.80r，球被指身淹没；改成管端 0.86r + 球 0.98r |
| 指尖变成蘑菇头 | 反过来：管端 0.54r + 球 1.02r，球比管粗一倍；球只该"把开口收圆"，不该"长出一个头" |
| 掌上有暗洞 | 手指/拇指是 `taperTube`，两端是开口。掌身太薄时开口半径超过该高度的截面，就露出管腔 |
| 掌像球顶长角 / 像三层汉堡 | 一颗椭球顶部收尖 → 手指从球顶戳出来；两三颗球叠 → 接缝留一圈横沟。改用超椭球 `boxBall` |
| 掌根像套了个褐色护腕 | 掌根球 0.096 比腕 0.070 粗 37%；手腕必须是全臂最细处（0.052），让手掌去包住腕 |
| 只数得出三根手指 | 手指直径是手长的 20%（人手 12%），四根把掌撑满，最外侧小指被掌缘吃掉 |
| 无名指和小指整根消失 | 手掌横跨在前臂上、深度相同，前臂的管子把这两根指挡住；腕点前移 0.034 让手落在臂的**前方** |

## 玩法数值

- 总分 = 跑动距离 + 奶龙数量 × 10
- 距离越远速度越快（12.5 → 23.5），每 520 米左右随机切换场景
- 场景：城市街道 / 草地森林 / 云端糖果世界
- 增益道具：无敌护盾（4.2s）、加速（5s，视野拉宽）、奶龙磁铁（6s）
- 最高分存本地 `localStorage`

## 大笑音效（用你自己的音频）

`res/laugh.mp3` 就是开场 / 死亡时那声大笑（来自 `res/奶龙大笑_爱给网_aigei_com.mp3`，复制了一份英文名，
避免中文路径在某些浏览器里 404）。想换声音直接覆盖这个文件即可。

原音频 10.2 秒，里面是三段"哈哈哈"。代码只播到 **3.8 秒**——那是第一段笑收尾的气口，接着 0.6 秒淡出，
不会一直笑到跑步中途盖住音乐和音效。想让它笑完整，改 `game.js` 里 `AudioSys` 顶部的：

```js
var LAUGH_HOLD = 3.8, LAUGH_FADE = 0.6;   // 笑多久后开始淡出、淡出多长
```

行为细节：
- 同一段笑声不会叠着播：正在响时再触发会直接复用，不打断重头开始
- `res/laugh.mp3` 缺失或无法解码时，自动回退到内置合成笑声（`synthLaugh()`），不会没声音
- 点击"开始"后会等 0.8 秒再起背景音乐，让笑声先出来

## 背景音乐（跑动时才响，开头结尾不响）

`res/bgm.wav` 是用 `tools/make_bgm.py` **合成**出来的，没有版权问题，也不用联网：

```bash
py tools/make_bgm.py        # 重新生成 res/bgm.wav
```

- **138 BPM · 8 小节 · 13.91 秒循环**；芯片音乐风：主旋律（带限方波 + 一点锯齿做身体）
  + 八分音符弹跳贝斯 + 底鼓 / 军鼓 / 闭镲。想改调式、速度、旋律，直接改脚本里的
  `BPM` 和 `MEL` 表再跑一遍即可。
- **为什么是 WAV**：机器里没有 ffmpeg / lameenc，编不了 mp3。WAV 反而更好——
  `<audio loop>` 播 WAV 没有编码器 padding，循环接缝听不出来；mp3 会在头尾各塞一点
  静音，loop 时会有可闻的断点。
- **无缝循环的做法**：多渲染 2.2 秒的尾巴，再把尾巴叠回文件开头，
  末尾音符的延音就自然绕回第一拍了。
- 音量：`AudioSys` 里的 `FILE_BGM_VOL = 0.42`。大笑是 0.92，BGM 压低才不盖住笑声和碰撞音效。

**播放时机**（`startRun` / `die` / `revive` / `visibilitychange`）：

| 阶段 | 音乐 |
|---|---|
| 开场动画 / 开始界面 | 不响 |
| 跑动中 | 响（点开始后延迟 0.8 秒淡入 0.9 秒，让笑声先出来） |
| 撞击瞬间 | 0.42 秒淡出 |
| 复活后 | 立即淡入 |
| 切到后台标签页 | 暂停；切回来且还在跑才恢复 |

最后一条靠 `bgmWanted` 标记实现——只记「按流程现在该不该有音乐」，
而不是看当前响不响，否则在结算画面切一下标签页回来音乐会自己响起来。

合成音兜底仍在（`synthBGM`）：文件缺失或解码失败时自动接管，不会出现没声音的情况。

除大笑外，其余音效都是 WebAudio 实时合成的，没有音频资源依赖：
- `laugh()` —— 奶蛙雷霆大笑（开局 + 死亡各播一次，优先读 `res/laugh.mp3`）
- `coin()` / `jump()` / `buff()` / `hit()` —— 吃奶龙、跳跃、拾取增益、撞击

## 常改的参数

都在 `game.js` 顶部的 `CFG`：

```js
LANES: [-1.95, 0, 1.95]   // 三条道的 x 坐标
BASE_SPEED: 12.5          // 起始速度
MAX_SPEED: 23.5           // 满速
RAMP: 1100                // 多少米后跑到满速
JUMP_V: 10.4 / GRAVITY: 30// 跳跃高度 1.80 米、滞空 0.69 秒
DUCK_TIME: 0.62           // 下滑下蹲持续时长
THEME_LEN: 520            // 场景切换间隔（米）
EGG_SCORE: 10             // 每只奶龙的分值
```

生成节奏在 `spawnPattern()` 里，`G.nextSpawn` 那行控制障碍行间距：
`lerp(26, 17, diff)` —— 从 26 米逐渐收紧到 17 米。

## 扩展方式

- **加障碍物**：在 `OB` 里加一个构建函数，返回 `{ obj, hit:{ y0, y1, hx, hz }, name }`，
  再把它加进 `OB_KEYS` 和 `spawnPattern()` 的类型抽取里即可。
- **加场景**：往 `THEMES` 加一组配色，再写一个 `propXxx()` 装饰物构建函数，
  加进 `PROP_BUILDERS` 数组（顺序要和 `THEMES` 对应）。
- **加道具**：`buildBuff(type)` 加外观，`applyBuff(type)` 加效果。
- **换广告 SDK**：只改 `playAd()`，倒计时结束后调用 `revive()`。

## 性能说明

- 全部几何体 / 材质缓存复用，装饰物按场景预建三套、切场景只切显隐
- 像素比上限 2，首 120 帧测平均帧时间，超过 24ms 自动降分辨率
- 无阴影贴图（用圆形贴地假阴影），无后处理，单光源 + 半球光
- 障碍/奶龙/装饰全部走"向前推进 + 回收"，不 GC 抖动

## 安卓 App

`android/` 里是一个完整可构建的 Android 工程（WebView 壳），
游戏本体 100% 离线打包进 assets，minSdk 23 / targetSdk 34。
（清单里声明了 `INTERNET`，只给「开发模式」用；正式玩法走 `setBlockNetworkLoads(true)`，
一个请求都发不出去。）

**不用装 Android Studio 也能出包**（工具链免安装，约 600 MB）：

```bash
py tools/install_toolchain.py    # 一次性：JDK 17 + android-34 + build-tools 34 + adb + 调试签名
py tools/build_apk.py            # → android/app/build/outputs/apk/奶蛙快跑-v1.1.apk（4.77 MB）
py tools/install_apk.py          # 手机插 USB 就一条命令装上并启动
py tools/dev_server.py --watch   # 开发模式：改完 JS 保存，手机上自动重载，不用重新出包
```

`build_apk.py` 跳过 Gradle，直接用 SDK 的 `aapt2 → javac → d8 → zipalign → apksigner`
手工出包。两个坑记在这：**① aapt2/zipalign 在 Windows 上不认中文路径**
（报 `failed to open directory: 系统找不到指定的文件`），所以先拷到
`~/naiwa-toolchain/build` 这种纯 ASCII 目录再编；**② manifest 里不能写 `package`**
（AGP 8 不允许），但 aapt2 link 又必须有，所以在构建沙箱里注入一份，源文件保持干净。

也可以走 Android Studio：打开 `android/` → 插手机点 Run。详见 `android/README.md`。

### 开发模式（改 JS 不用重新出包）

调手感时改一行 `game.js` 就要传 5 MB 到手机重装，太慢。`py tools/dev_server.py`
会把 App 变成「电脑页面的浏览器」：

```bash
py tools/dev_server.py          # 起服务 + adb reverse + 手机自动打开
py tools/dev_server.py --watch  # 保存 game.js 就自动重载
py tools/dev_server.py --stop   # 收工
```

手机上右下角出现 **DEV ↻** 角标，点一下刷新。走的是**USB 反向映射**
（`adb reverse tcp:8000 tcp:8000`），不需要同一 WiFi，也不怕校园网的客户端隔离。
点桌面图标正常启动 = 立刻回到离线 assets 版本，装给别人的包里这条路径走不到。

`MainActivity` 侧的实现要点：`dev_url` 由 intent extra 传入、`onNewIntent` 按新
intent 重新判定（`singleTask` 不会重建 Activity）、每次 `loadUrl` 都带 `?_t=时间戳`
（同 URL 连发 WebView 可能不重新请求）、`setBlockNetworkLoads(false)` 只在 dev 分支开。

安卓版操作是**四向滑动**（在 `game.js` 输入模块里实现，桌面鼠标拖拽同一套逻辑）：
左/右滑换道、上滑跳、下滑蹲并保持约 0.9 秒、轻点也能跳。三条硬规则：

1. 手势绑在 `document` 而不是 canvas —— HUD 和结算卡这些覆盖层会吃掉 canvas 的触摸，
   手指落在屏幕上半部就滑不动；
2. 一次滑动只出一个动作（`gesture.fired` 锁到抬手）—— 旧版每移 30px 就重置起点，
   一记长滑能连换两道；
3. 方向在**首次越过阈值**那一刻定死（阈值按屏幕短边 4.5% 自适应），斜滑也能稳定归到主轴。

打包细节（自动播放、WebGL 硬件加速、音频 seek、刘海屏、切后台暂停 BGM 等）
都记在 `android/README.md` 第五节，逐条对应"不做就会出问题"的真实坑。

## 版本管理

仓库在 `main` 分支，远程是 **https://github.com/PJH123720/NAIWA**（公开仓库，
GitHub 建仓时生成的 `LICENSE` 已合并进来，历史是线性的）。

```bash
git status                  # 改了什么
git diff game.js            # 看具体改动
git add -A && git commit -m "描述"   # 存档
git log --oneline           # 历史
git checkout .              # 后悔了，丢弃未提交的改动
git reset --hard <提交号>    # 回到某一次存档（会丢弃之后的改动，慎用）
git push                    # 推上去（首次已设好 upstream，之后直接 push 即可）
```

**不入库的东西**（`git status --ignored` 能看到，磁盘上都还在）：

| 路径 | 为什么 | 体积 |
|---|---|---|
| `res/models/raw/*.glb` | 图生 3D 的原始 GLB，出包只用 `actors/*_glb.js` | 168 MB |
| `android/app/build/`、`*.apk` | 构建产物，5 秒就能重新生成 | — |
| `android/.../assets/www/` | 由 `tools/sync_android_assets.py` 从根目录同步生成 | 7 MB |
| `.shots/` | headless 调试截图 | — |
| `.tmp_* / .c_* / .r_* / .ref* / .bak_*` | 图生 3D 流水线留在根目录的中间文件 | 7 MB |

想连原始模型一起备份：删掉 `.gitignore` 里 `res/models/raw/*.glb` 那行再提交即可。
`res/models/naiwa_ai.glb`（23 MB）和 `.zip`（18 MB，原生 OBJ + PBR 贴图）**是入库的** ——
它们是主角模型的唯一源文件，重新生成要烧图生 3D 的每日额度。
